# P1e5: one candidate, all 500 frozen openings

The controller adds one job to parent 20d361afaa6767656ed6a5444c23f22dabba8d50. It measures all 500 cases with one executable from exact source 56376838ffea91169321895f8e81abec2137dd46, whose runtime is P1e a10. Features are the canonical KEEP-R1 core6 plus experiment-lazy-ko-damage. Generic x86-64, one measurement CPU, no observer and no LAB environment are mandatory. No original/candidate results are spliced together; a mixed-source ledger is rejected.

The benchmark Rust source, B17 corpus, ordered case list, joint seeds, sampling policy, result schema and aggregation formulas remain byte unchanged. The original B17 run36780443039 emitted all500 descriptions; their saved raw bytes were validated against its ledger and the corpus. original-plans.json freezes each description SHA256 and byte count. All500 candidate descriptions must reproduce those original bytes before any measurement begins. Measurements use those checked plans and samples16/64/256 with the same five seeds per opening. The unmodified benchmark compares sampled full State plus Suspension against the same candidate's exact Full factored reference; the current-HP-removed projection remains a separately reported auxiliary metric. Full support is represented symbolically, not exported as every state row.

A fresh single candidate build runs the seven named benchmark correctness tests. Copied actual compiler fingerprints, executable hashes, command/log identities and source/corpus/plan hashes are checked again before measurement. The prior independently audited run36835592119 supplied61 correctness test executions and104 full-State corpus cases for this exact source. Its audit is copied byte-exact and pinned; those61 executions are reused evidence, not claimed as fresh in P1e5.

Each child has at most60 seconds and6GiB RSS. The measurement stage has1200 seconds, with its remaining time passed into each child; Python validation and final bookkeeping can finish after that deadline. The single job has30 minutes, leaving build/upload margin. All descriptions precede all measurements. Every success, failure, pending/not-run entry, raw stdout/stderr and process CPU/wall/RSS record is preserved. A missing, changed, failed or timed-out case leaves complete=false and official_metrics=null. Fully completed metrics describe this candidate on this runner only. The original B17 incomplete aggregate is not repaired.

Previous baseline cost was one job, not shards: 451 job seconds,33 build-step seconds and389 measurement-step seconds. Its500 descriptions took6.493 child seconds;499 completed measurements took107.278 child seconds and one timed-out case took60.023 seconds. These saved observations informed the single-job choice; they are not a paired speed comparison with this new VM.

P1e5 does not prove equivalence to the still-unfinished original opening0429 reference, reproduce paper hardware/input/result keys, authorize adoption, change production/default features, require AVX2, or report a cross-VM speedup. Original B17 and P1e2 failed/inconclusive artifacts remain unchanged. Freshness and completeness are independent of whether the candidate is faster.
