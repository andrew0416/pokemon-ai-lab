# S25d — 상대 응수 우선 확장 실험

- 원본: S25b `a0f7b556e30095e85ce56013c0e7d1f08206f03d`.
- 수정본: `0501eeb7220bcc3f5e2f00145c970fa350666031`.
- GitHub: https://github.com/andrew0416/pokemon-ai-lab/actions/runs/36999721226
- 기능: `lab-search/experiment-response-sweeps`, 기본 OFF, 범용 x86-64.
- 생산/R1 구성, 기존 실험 소스와 결과, 공유 체크아웃은 변경하지 않는다.

## 수정 원리

1. root의 행·열 전략 확률을 곱해 상대적으로 드문 반격을 밀어내던 선택을 바꾼다.
   각 칸의 우선순위를 `(p[row] + q[col] + 1/(rows+cols)) / (1+visits)`로 두고,
   그 칸 아래 미완료 미래를 확장한다. 어느 한쪽이 유력하면 상대의 드문 응수도
   검토한다. 양의 균등항은 두 쪽 모두 현재 확률 0인 칸도 언젠가 방문하게 한다.
   이 선택기는 결정적이다. seed 반복은 타이밍 반복이며 무작위 독립 탐색이 아니다.
   기존 PUCT exploration/prior는 새 선택기의 순위 계산에 쓰지 않는다.

2. 자식의 최종 scalar value가 bitwise 동일하면 상위 payoff도 그대로다.
   또한 변경된 칸의 행·열 확률이 **둘 다 정확히 0**이면 어느 단측 best-response
   기대값에도 기여하지 않는다. 이 두 경우 기존 equilibrium/value/gap을 재사용한다.
   한쪽만 0이거나 아주 작은 양수일 때 이 조건으로 생략하지 않는다.
   수치가 바뀌는 경로는 부모까지 다시 풀고, 완결된 root만 공개한다.

3. 노드의 position을 `Option<Box<P>>`로 둔다. horizon/terminal leaf는 value만
   계산하고 position을 보관하지 않는다. 모든 칸과 모든 확률 자식이 완료된 노드도
   position을 해제한다. 값이 그대로여도 완료 상태는 모든 조상에게 전파한다.
   트리의 값·행동·간선은 남는다. DAG, 상태 병합, 노드 상한 증가를 도입하지 않았다.

## 검증 범위

로컬은 opt0 논리 검사만 수행한다. 수정본 38개, 기존 실험 36개, 독립 엔진 기준
CLI 1개, 기본 OFF 17개, clippy를 통과했다. CI에서는 R1 기능과 함께 새로 빌드하고
검증한다. 기존 7입력·3seed·3초/15초 기준을 고정하여 3개 방법 63회를 측정한다.
문제 국면은 별도로 기존/수정본 선택 탐색을 최대 120초 완주 대조한다.

기준 재귀와 scorer는 S25b와 byte-identical이다. 기준 행렬은 동일 engine adapter와
RM+를 공유하므로 독립 전투 시뮬레이터 검증은 아니다. 수정 후에도 local gap은
미탐색 미래의 안전성을 보증하지 않으며, 실제 파티 2개에는 깊이2 기준해가 없다.
측정 결과와 채택 판단은 `RESULTS.md`, 원본 검산은 `AUDIT-36999721226.json`에 기록한다.
