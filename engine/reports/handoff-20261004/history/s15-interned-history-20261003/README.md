S26e 후보 2: 관측·자기 행동 이력 공유

동결된 S14 소스 `ec9b72e149b9d72e762e4023a84365e3f72a2ff5`에 대한 독립 실험이다. 기존 다섯 저장 최적화와 완성 상태 소유권 전달을 모두 적용한 기준에서 비교한다. `experiment-interned-history`는 기본 OFF이며 기존 Vec 경로를 유지한다. core의 전투 규칙·열거·평가기와 CFR 풀이기 코드는 수정하지 않는다.

빌더는 Histories 저장 인터페이스로 Plain과 Interned를 선택한다. Plain은 기존 Vec<Memory> 복사·Debug 형식화를 수행한다. Interned는 문자열을 atom으로 등록하고 `(이전 링크 ID, 이벤트)`를 full Eq로 등록한다. 물리 분기는 각 플레이어의 정수 ID만 복사하며, 같은 ordered history의 긴 정보 키는 처음 한 번만 만든다. Hash는 버킷 선택에만 쓰이며 충돌을 같은 이력으로 취급하지 않는다.

외부 정보 키와 Cursor 호환성을 유지하기 위해 두 경로 모두 같은 `Memory<S>` enum의 derived Debug를 사용한다. 후보는 문자열 atom을 대여한 `Memory<&str>` 이력을 최초 형식화할 때만 복원한다. 공개 이력의 Vec<String>, BTreeMap 정렬, 공개 그룹 확장 순서, 정보집합 등록 순서와 모든 물리 상태는 기존대로 남긴다. compiler의 own_sequence interning과 별개의 빌더 계층 최적화다.

풀 열거와 성장 탐색 모두 별도 opt-in API를 제공한다. 새 CLI는 실제 엔진과 명시적 observed table 양쪽에 새 저장 경로를 연결한다. 기존 writing/owned API, 기본 기능, 강제 교체 닫기, 예산 중단 시 직전 완성 결과 보존, 도메인 호출 순서와 오류를 유지한다.

검증은 최대 128결정의 문자열/완전 회상, 강제 해시 충돌, 숨은 세계·상대 행동 비누출, 동일 suffix/다른 과거, builder fork, 기존 모든 예산 경계, 104개 합성 도메인 호출 이력, 양쪽 좌석의 실제 엔진 연결을 포함한다. 관측용 카운터는 시간 측정 바이너리에서 제외한다. 별도 LP 검증은 이전 문제 묶음을 새 경로로 재실행하며 새로운 독립 문제 수로 세지 않는다.

개발 중 발견한 초기 빌드 문제는 수정 이력에 보존한다: 테스트의 generic hasher 타입 명시, CLI cfg import 중복, Clippy의 frontier type alias 요구. 초기 형식화 초안은 중복 문법을 제거하고 공통 Memory enum을 사용하도록 정리했다. 기대 결과를 바꿔 불일치를 숨기는 수정은 없다.

로컬에서는 로직 검사만 한다. GitHub에서 6국면 × 성장/전체 열거를 같은 portable x86-64 바이너리의 Vec/정수 링크 선택으로 비교한다. ABBA/BAAB 9블록씩 단일 논리 CPU에서 측정한다. S14의 밀리초를 다른 실행의 밀리초와 직접 나누지 않는다. 메모리 최고 사용량과 승률은 평가하지 않는다.

실행 `37085660921`은 4분 8초에 성공했다. 소스 `cab569eec64dc3213bedf934f69e7c4a78ef38c4`는 동결했다. 12개 동일 계산량 비교의 원시 108블록·432표본·900회 계산 및 95% bootstrap 구간을 재검산했다. 결과는 `RESULTS.md`, 출처와 검산은 `AUDIT-37085660921.json`에 있다.

조건부 후보로 보관한다. 2세계/4세계의 성장·전체 열거는 3.49~6.29% 추가 단축됐고 좁은 3턴은 2.30~2.37% 단축됐다. 모래는 성장 2.42%·전체 열거 0.82%, 턴 중 교체의 전체 열거는 1.54% 느려졌다. 이 세 회귀는 이번 러너의 95% 구간 전체가 회귀 방향이다. 1세계 성장의 0.73% 개선은 구간이 0을 걸치므로 확정적 이득으로 취급하지 않는다. 전 국면에 합산 적용하거나 자동으로 고르는 정책은 추가하지 않았다. 다음 후보의 대조군은 안정적으로 개선된 S14를 유지하며 S15는 필요할 때 별도로 조합 비교한다.
