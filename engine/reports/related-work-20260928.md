# 관련 공개 프로젝트 조사 (2026-09-28)

질문: Rust 기반·더블 지원·되돌리기(make/unmake)가 있는 엔진이 이미 공개돼 있는가.
답: **없다.** 가장 가까운 둘은 PokaiEngine(미공개)과 pokeuraou(Rust 해결기는 있으나 되돌리기 없음, 라이선스 미표기).
수집일 2026-09-28, 검색은 미국 기준 결과라 누락 가능. 아래 수치는 각 저장소·논문의 자체 보고이며 재현하지 않았다.

## 2. 참고할 것 (우리 보드 항목에 대응)

### PokaiEngine (열거)
| 그들 | 우리 대응 | 비고 |
|---|---|---|
| **HP를 "흡수한 데미지 롤의 분포"로 상태 안에 실음.** 롤이 KO 문턱을 걸칠 때만 상태를 나누고, 수치만 다르고 행동이 같은 분기는 한 상태에 머무름 | **P1a/P1b (AC 진행 중)** — 우리 설계 방향과 같음. "행동을 바꾸는 문턱"(KO·열매·기합의띠·HP 비례 위력) 목록이 핵심 | 그들 중앙값 9분기/행동, 최대 18,176 |
| 32분기 상한에서 확률 질량 99.5%를 1.0 ms에 덮음 — 표본보다 빠르고 정확 | **P1c** 결과 상한·근사 모드의 목표치 | |
| 상대의 숨은 배분을 독립 가정 아래 상태 안 분포로 실음, 정성적으로 갈릴 때만 분리 | **S23** 모델 ② 확장 — 지금은 후보별 국면을 따로 풀어 가중 평균 | |
| 한 턴의 fork된 상태들을 공유 가능한 속성으로 묶어 함께 진행 | P1b 구현 힌트(프런티어를 묶음 단위로 진행) | |
| 컴퓨트 모드 턴당 0.08 ms(Showdown 2.0 ms) | 우리 열거 1회 1.7 ms/31결과 → **P2–P4 (YY)** 의 목표 자릿수 | |
| 일치 검증: 무작위 개막 500 + Showdown 리플레이 256 + 합성 600 + 래더 500경기, 버그 4개 발견 | 우리 말뭉치 1,781국면 + fixture 1,150 — **리플레이 기반 말뭉치**는 없음 (아래 V13) | |

### PokaiTrainer (탐색)
| 그들 | 우리 대응 |
|---|---|
| 공개 믿음 상태 β=(s, b), b는 상대 4/6 선출의 사후분포(선두 공개 전 ≤15, 후 ≤6) | 우리 모델 ②는 배분 후보; **선출 후보**는 없음 → S23에 추가 후보 |
| 각 결정을 교대 갱신 **linear CFR**로, 에이전트 후회표 1개 + 세계별 상대 후회표 | 우리는 RM+ 행렬 게임 + 믿음 가중 평균 행렬. 세계별 후회표 분리는 모델 ② 정확도 개선안 |
| 서브게임 성장: PUCT-CFR 혼합 걷기, 비용 단위 예산(턴 1, 교체 ≪1), 믿음 폭 |W|^ρ로 스케일 | **S24c (AD)** 깊이 3 예산 설계에 참고 — 깊이 고정보다 비용 예산 |
| 행동 추상화: 루트 전부(~100/슬롯), 내부는 정책 사전확률 상위 16, 상대 루트 상위 16 + 교체·기믹 예약 슬롯 | 우리 double oracle·약지배 제거와 보완적; 정책 사전확률은 네트워크 필요 |
| 가치망 5.4M 파라미터 트랜스포머, 리플레이 122,804판 행동 복제로 초기화 | S12 적합의 먼 미래. **"정책만"은 재료 휴리스틱 탐색에 71% 패배 — 탐색이 실력**이라는 결과는 우리 방향 지지 |
| 배분 추론: 관측 결과에 대한 엔진 질량으로 후보 재가중(손으로 만든 공식 없음) | 우리 모델 ② 갱신과 동일 |

### pokeuraou (Champions M-C 형제 프로젝트)
| 그들 | 우리 대응 |
|---|---|
| **"추측하지 않고 거부"** 정책 + 거부 사유 집계로 다음 구현 순서 결정(`refused-wide.json`) | 우리 R0 거부 감사·`REFUSALS.md`와 동일 철학 |
| 불일치를 **flagged(사전 신고) / silent(무신고)** 로 나눠 보고; 1턴 4.9% / silent 2.9%, 데미지 0.000%(1,731타격), 교체 0.000% | 우리는 silent 0(1,781국면). 그들 `tools/diverge_report.py`의 **효과별 lift = P(효과\|불일치)/P(효과\|일치)** 는 불일치 원인 자동 귀속에 유용 → parity_sweep에 추가 후보 |
| 오라클: Showdown의 모든 RNG 호출 기록 → 결정적 재생 | 우리 `--mode fixed --staged`(JJ)와 같음 |
| 부가효과 접기(fold)가 정책을 8.7% 바꿈을 실측하고 분기로 전환(비용 1.20배) | 우리는 처음부터 분기. 급소·부가효과 접기 근사를 넣을 때의 참고 수치 |
| LP(HiGHS) 24×24×4 믿음 클래스 2.2 ms; 믿음 클래스는 군집 4개(16까지 시험), 클래스 격자의 최량우선탐색으로 직적 회피 | 우리 RM+ 대비 LP는 정확 균형. **믿음 클래스 군집화**는 S16/S23에 참고 |
| 가치함수 40.6k 파라미터 반대칭 MLP: AUC 0.907 vs HP비 0.909(거의 같음), log loss 23% 개선 | 손 휴리스틱이 순위에는 충분, 보정에만 차이 → S12 기대치 조정 |
| **PGO 빌드(`pgo.sh`)**, 메모리 감시, 4스레드 이상은 배속 정체 | **P6 PGO** 신규 후보(싼 성능 이득) |
| 웹 UI 대국·검토 모드, 자기대전·표준 데이터 도구 | 범위 밖(목표는 엔진) |

## 3. 참고하지 않을 것
- pokeuraou 코드 자체(라이선스 없음). pokemon-showdown-rs(MIT)는 1:1 이식이라 구조가 다르고 더블·되돌리기 없음.
- PokaiTrainer의 학습 파이프라인(리플레이 12만 판·자기대전·5.4M 네트워크) — 현재 목표(엔진) 밖.

## 4. 보드에 올린 항목
- `P6-pgo`: 릴리스 바이너리 PGO(프로파일 유도 최적화) — 벤치 3국면으로 프로파일, 배속 측정.
- `V13-replay-parity`: Showdown 공개 리플레이(M-C)를 말뭉치 출처로 추가(리플레이 로그 → 핀 국면).
- `V14-diverge-lift`: parity_sweep에 효과별 lift 귀속 보고 추가(불일치가 다시 생길 때용).
- `S28-belief-classes`: 모델 ②의 배분 후보를 군집(클래스)으로 묶고 선출 후보(4/6)를 믿음에 추가.
